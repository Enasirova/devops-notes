Good. This confirms the node is SSH-launched, so the problem is in the SSH launch flow, not a random stale UI object.

What you know now:

launcher type: SSHLauncher
Jenkins tries to connect to 10.90.213.11:22
remote root: /Users/jenkins/slave
credentials id: macosbuild3
no custom Java path is configured
retention is Always, so Jenkins expects it to stay online
What this means in simple words:

Jenkins will SSH to the Mac
then try to start the Jenkins agent under /Users/jenkins/slave
it expects java to be available in the remote shell path
if any part of that fails, the node stays offline with Channel: null
Most likely failure points now are:

Jenkins cannot authenticate with credential macosbuild3
Jenkins can SSH, but not as the expected user
remote directory /Users/jenkins/slave does not exist or is not writable
Java is not installed or not in PATH for non-interactive SSH sessions
macOS login shell/profile behaves differently for Jenkins than for manual SSH
host key verification failure in Jenkins
stale remoting process / broken startup command on the Mac
