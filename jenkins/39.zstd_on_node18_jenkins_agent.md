# 1. What is zstd

`zstd` (Zstandard) is a modern compression algorithm created by Meta.

Purpose: compress files **faster and more efficiently** than traditional tools.

## Common compression tools

| Tool | Purpose |
|-----|------|
| gzip | traditional compression |
| zip | archive compression |
| zstd | modern fast compression |

### Advantages

- very fast compression
- very fast decompression
- better compression ratio than gzip
- widely used in modern infrastructure

# 4. What "precompute compressed version" means

Normally compression happens **during the HTTP request**.

## On-the-fly compression

    Browser request
        ↓
    Web server compresses file
        ↓
    Compressed response

This consumes **CPU resources on the server**.

---

## Precomputed compression

Compression happens **during the build pipeline**.

    Build pipeline
        ↓
    Generate assets
        ↓
    Compress assets
        ↓
    Store compressed files
        ↓
    Web server serves them directly

Example output files:

    app.js
    app.js.gz
    app.js.zst

Server response header:

    Content-Encoding: zstd

Benefits:

- faster responses
- lower CPU usage
- better scalability

---

# 5. Why use zstd

Modern browsers support multiple compression formats.

| Algorithm | Speed | Compression |
|----------|------|-------------|
| gzip | medium | medium |
| brotli | slower | very good |
| zstd | very fast | very good |

zstd provides a **great balance between compression ratio and speed**.

This is useful for:

- large JavaScript bundles
- large CSS files
- modern web applications

# problem on the way: Cloudflare does not support zstd from origin

## 1. Cloudflare does not support zstd from origin

According to Cloudflare documentation:

https://developers.cloudflare.com/speed/optimization/content/compression/#content-compression-from-origin-servers-to-the-cloudflare-network

Cloudflare currently supports compression from origin using:

- `gzip`
- `brotli`

But **zstd is not supported from origin servers to Cloudflare**.

This means if the origin server sends:

```
Content-Encoding: zstd
```

Cloudflare will not use it.

Therefore generating `.zst` files in the pipeline would likely bring **no benefit**.

---

## 2. Current nginx setup does not support brotli or zstd

The current setup uses **free / open-source nginx**.

This version supports:

```
gzip
```

But **does not support**:

```
brotli
zstd
```

Trying to enable unsupported compression modules caused a **deployment crash** previously.

This likely happened because nginx was configured with directives that the installed binary does not support.

---

## 3. Cloudflare can handle compression automatically

Cloudflare can recompress responses before delivering them to the browser.

Typical flow:

```
Origin server (nginx)
      ↓
Cloudflare
      ↓
Browser
```

Cloudflare can automatically serve responses using:

- Brotli
- Gzip

This means compression can be handled by **Cloudflare instead of the origin server**.

---

## 4. Current options identified

Upgrade to **NGINX Plus**, which includes additional features and modules.

Benefits:

- simpler infrastructure
- no nginx module changes
- Cloudflare automatically optimizes delivery
