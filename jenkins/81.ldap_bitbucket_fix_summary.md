# LDAP and Bitbucket plugin fixes after Jenkins update

This is a short recap of what finally made LDAP login and Bitbucket webhooks work after the Jenkins/plugin update.

# LDAP

## Problem

After updating plugins, Jenkins login failed.

Log error:

```text
javax.naming.PartialResultException: Unprocessed Continuation Reference(s)
PluginClassLoader for ldap
DefaultLdapAuthoritiesPopulator.getGroupMembershipRoles
LDAPSecurityRealm
```

This happened during LDAP group lookup after user authentication. The newer LDAP plugin did not handle the AD continuation/referral result the same way as the older version.

## Temporary fix that restored login

The LDAP plugin was restored from the plugin backup.

```bash
sudo cp -a plugins.20260601-073342/ldap* plugins/
sudo chown -R jenkins:jenkins plugins/ldap*
sudo systemctl stop jenkins
sudo systemctl start jenkins
```

After this downgrade/restore from backup, login worked again.

## Final YAML/config fix for newer LDAP behavior

The real config issue was that LDAP group lookup was too broad. The old YAML only had:

```yaml
groupSearchFilter: "(&(objectCategory=Group)(cn={0}))"
rootDN: "DC=ad,DC=ifortuna,DC=cz"
userSearchBase: "OU=Users,OU=_Production"
```

There was no explicit `groupSearchBase`, so Jenkins could search for groups too broadly under the root domain and hit AD continuation/referral behavior.

The fix was to add explicit group lookup settings:

```yaml
groupMembershipStrategy:
  fromGroupSearch: {}
groupSearchBase: "OU=Groups,OU=_Production"
groupSearchFilter: "(&(objectCategory=Group)(cn={0}))"
```

This was tested in the UI first. After setting group search base to:

```text
OU=Groups,OU=_Production
```

you logged out and logged in again successfully.

Then the same LDAP change was persisted in `jenkins.yaml`.

# Bitbucket

## Problem

After updating the Bitbucket/Blue Ocean plugin group, manual multibranch scan worked, but automatic push webhooks did not discover new branches.

Important log lines:

```text
bitbucket-webhooks plugin found, skipping this deprecated implementation.
No processor found for the incoming Bitbucket hook. Skipping.
java.lang.Exception: No processor found that supports this event.
```

Meaning: Jenkins received the webhook, but the Bitbucket webhook payload did not match the configured Jenkins webhook processor.

The old setup was:

```text
Bitbucket Post Webhooks add-on
  -> old embedded Jenkins Bitbucket Branch Source plugin-webhook processor
```

The working new setup became:

```text
Bitbucket Post Webhooks add-on
  -> Jenkins bitbucket-webhooks plugin
  -> Bitbucket Branch Source
```

## Plugin/UI changes

You installed the new plugin:

```text
bitbucket-webhooks
```

Then the Jenkins Bitbucket endpoint was changed to:

```text
Post Webhooks for Bitbucket REST 1.0
```

This alone was not enough, because Bitbucket still had the old webhook entry.

## YAML/JCasC change

The Bitbucket endpoint config also had to be fixed in `jenkins.yaml`.

Old production/not-updated style:

```yaml
bitbucketEndpointConfiguration:
  endpoints:
  - bitbucketServerEndpoint:
      credentialsId: "bb-jenkins-userpwd"
      displayName: "ftnBitb"
      manageHooks: true
      serverUrl: "https://app-bitb-shared.o.dc1.cz.ipa.ifortuna.cz"
```

Test/current working style:

```yaml
bitbucketEndpointConfiguration:
  endpoints:
  - bitbucketServerEndpoint:
      displayName: "ftnBitb"
      serverURL: "https://app-bitb-shared.o.dc1.cz.ipa.ifortuna.cz"
      webhook:
        postWebhooks:
          credentialsId: "bb-jenkins-userpwd"
          manageHooks: true
bitbucketPluginConfiguration: {}
```

So the Bitbucket YAML migration was:

```text
removed old direct credentialsId under bitbucketServerEndpoint
removed old direct manageHooks under bitbucketServerEndpoint
changed serverUrl -> serverURL
added webhook.postWebhooks.credentialsId
added webhook.postWebhooks.manageHooks
added bitbucketPluginConfiguration: {}
```

The important extra Bitbucket-related YAML line/block was:

```yaml
bitbucketPluginConfiguration: {}
```

## Final step that made it work

The old Bitbucket Post Webhook was deleted in Bitbucket.

Then the Jenkins multibranch job was re-saved, which caused Jenkins to recreate the Bitbucket webhook using the new `postWebhooks` setup.

After that, a push triggered multibranch indexing:

```text
Received io.jenkins.plugins.bitbucket.webhook.moveworkforward.processor.PostWebhooksPushEvent CREATED event
Checking branch bbwebhookv1 from TOOL/nasekatest
'Jenkinsfile' found
Scheduled build for branch: bbwebhookv1
```

Final working state:

```text
bitbucket-webhooks installed
Jenkins endpoint = Post Webhooks for Bitbucket REST 1.0
jenkins.yaml uses webhook.postWebhooks
old Bitbucket Post Webhook deleted
Jenkins recreated the hook
push triggered multibranch indexing
branch became visible
```
