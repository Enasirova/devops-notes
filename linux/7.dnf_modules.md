# DNF Modules

## What This Is About

This note explains DNF modules.

Main idea:

```text
DNF modules let us choose specific supported versions, called streams, for some software stacks.
```

This is important on CentOS, Red Hat Enterprise Linux, and Fedora.

## Why Modules Exist

Enterprise Linux systems are designed to be stable.

That means:

```text
Package versions should not change dramatically during one OS release.
Security fixes and bug fixes are preferred over large feature upgrades.
```

This is useful because production systems need reliability.

For example:

```text
An application is tested with one package version.
The OS keeps that version stable for a long time.
The application is less likely to break because of unexpected feature changes.
```

But sometimes we need a newer version of a specific tool.

Examples:

- NodeJS
- PHP
- PostgreSQL
- Redis
- MariaDB
- Java runtimes

DNF modules solve this problem by allowing multiple supported version streams.

## Example Problem: NodeJS

NodeJS is a runtime for running JavaScript outside the browser.

It is commonly used for:

- APIs
- web servers
- highly concurrent web applications
- build tools
- command-line tools

NodeJS moves quickly.

Newer versions often include:

- new JavaScript features
- new runtime features
- performance improvements
- changed behavior

So an application may require a specific NodeJS version.

## Normal Install May Give An Older Version

Install NodeJS normally:

```bash
sudo dnf install nodejs
```

Then check the version:

```bash
node --version
```

Example:

```text
v16.19.0
```

This can look outdated compared to the current upstream NodeJS versions.

That is expected on enterprise Linux.

## Why The Repository Version May Be Old

On enterprise Linux, an older default version is not automatically bad.

It is intentional.

The goal is:

```text
Keep a reliable software foundation.
Avoid surprising feature changes.
Provide security and bug fixes for a supported version.
```

During a long OS support cycle, the distribution may keep the same default NodeJS version.

Example:

```text
NodeJS 16 stays the default.
Security fixes and bug fixes are backported.
The system does not automatically jump to NodeJS 18 or NodeJS 20.
```

This makes servers more predictable.

But if developers need NodeJS 18, we need a controlled way to opt in.

That is what DNF modules provide.

## What Is A DNF Module?

A DNF module is a package group.

```text
normal package = one product on the shelf
module = product with selectable editions
```

A modular package belongs to a module, and the module can offer different version lines.

Example:

`nodejs`

NodeJS may have several possible streams:

```text
nodejs:16
nodejs:18
nodejs:20
```


It usually represents:

- an application
- a language runtime
- a database system
- a set of related tools

Examples:

```text
nodejs
php
postgresql
redis
mariadb
```

Modules can have different streams.

## What Is A Stream?

A stream is the selected version line of a module.

Example:

```text
nodejs:16
nodejs:18
nodejs:20
```

Meaning:

```text
nodejs:16  use the NodeJS 16 stream
nodejs:18  use the NodeJS 18 stream
nodejs:20  use the NodeJS 20 stream
```

The stream is not always available just because the upstream project has that version.

It must exist in your enabled repositories.

## List Available Modules

List all modules:

```bash
sudo dnf module list
```

This can produce long output.

To search for NodeJS:

```bash
sudo dnf module list nodejs
```

Example output may show:

```text
Name    Stream    Profiles
nodejs  18        common, development, minimal
```

Meaning:

```text
The nodejs module is available.
Stream 18 is available.
```

## Check Current Node Version

Before changing the module:

```bash
node --version
```

Example:

```text
v16.19.0
```

This means the current installed NodeJS binary is version 16.

## Enable A Module Stream

To enable the NodeJS 18 stream:

```bash
sudo dnf module enable nodejs:18
```

DNF will ask for confirmation.

Confirm with:

```text
y
```

Important:

```text
Enabling a module stream does not necessarily upgrade the installed package immediately.
```

It tells DNF which stream should be used.

## Upgrade After Enabling A Stream

After enabling the stream, run:

```bash
sudo dnf upgrade
```

This upgrades installed packages to versions from the enabled stream where possible.

Then check:

```bash
node --version
```

Example:

```text
v18.x.x
```

Meaning:

```text
NodeJS is now running from the NodeJS 18 stream.
```

## Full Example

Install NodeJS:

```bash
sudo dnf install nodejs
```

Check version:

```bash
node --version
```

List available NodeJS streams:

```bash
sudo dnf module list nodejs
```

Enable NodeJS 18:

```bash
sudo dnf module enable nodejs:18
```

Upgrade packages:

```bash
sudo dnf upgrade
```

Check version again:

```bash
node --version
```

## Why Enabling A Module Is Controlled

The default repository version stays stable.

Newer streams are available only when you choose them.

This gives administrators control.

Example:

```text
Developers test the application with NodeJS 18.
Administrator enables nodejs:18.
DNF upgrades NodeJS on purpose.
```

This is better than surprise upgrades.

## Modules Over Time

During one OS release, more streams may become available.

Example:

```text
At first, only nodejs:16 is available.
Later, nodejs:18 is added.
Later, nodejs:20 may be added.
```

The default version can stay stable, while newer streams are available for systems that need them.

## Summary

DNF modules are package groups with selectable version streams.

They are useful for software where version choice matters.

Examples:

```text
NodeJS
PHP
PostgreSQL
Redis
MariaDB
```

Important terms:

```text
module  package group, often an application or runtime
stream  version line of that module
```

Typical workflow:

```bash
sudo dnf module list nodejs
sudo dnf module enable nodejs:18
sudo dnf upgrade
node --version
```

This lets you opt in to a newer supported version while keeping the rest of the enterprise Linux system stable.
