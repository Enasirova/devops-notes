# DNF Modules

## What This Is About

This note explains DNF modules.

Main idea:

```text
DNF modules let us choose specific supported versions, called streams, for some software stacks.
```

This is important on CentOS, Red Hat Enterprise Linux, and Fedora.

## Why Modules Exist

Enterprise Linux systems are designed to be stable.

That means:

```text
Package versions should not change dramatically during one OS release.
Security fixes and bug fixes are preferred over large feature upgrades.
```

This is useful because production systems need reliability.

For example:

```text
An application is tested with one package version.
The OS keeps that version stable for a long time.
The application is less likely to break because of unexpected feature changes.
```

But sometimes we need a newer version of a specific tool.

Examples:

- NodeJS
- PHP
- PostgreSQL
- Redis
- MariaDB
- Java runtimes

DNF modules solve this problem by allowing multiple supported version streams.

## Example Problem: NodeJS

NodeJS is a runtime for running JavaScript outside the browser.

It is commonly used for:

- APIs
- web servers
- highly concurrent web applications
- build tools
- command-line tools

NodeJS moves quickly.

Newer versions often include:

- new JavaScript features
- new runtime features
- performance improvements
- changed behavior

So an application may require a specific NodeJS version.

## Normal Install May Give An Older Version

Install NodeJS normally:

```bash
sudo dnf install nodejs
```

Then check the version:

```bash
node --version
```

Example:

```text
v16.19.0
```

This can look outdated compared to the current upstream NodeJS versions.

That is expected on enterprise Linux.

## Why The Repository Version May Be Old

On enterprise Linux, an older default version is not automatically bad.

It is intentional.

The goal is:

```text
Keep a reliable software foundation.
Avoid surprising feature changes.
Provide security and bug fixes for a supported version.
```

During a long OS support cycle, the distribution may keep the same default NodeJS version.

Example:

```text
NodeJS 16 stays the default.
Security fixes and bug fixes are backported.
The system does not automatically jump to NodeJS 18 or NodeJS 20.
```

This makes servers more predictable.

But if developers need NodeJS 18, we need a controlled way to opt in.

That is what DNF modules provide.

## What Is A DNF Module?

A DNF module is a package group.

```text
normal package = one product on the shelf
module = product with selectable editions
```

A modular package belongs to a module, and the module can offer different version lines.

Example:

`nodejs`

NodeJS may have several possible streams:

```text
nodejs:16
nodejs:18
nodejs:20
```


It usually represents:

- an application
- a language runtime
- a database system
- a set of related tools

Examples:

```text
nodejs
php
postgresql
redis
mariadb
```

Modules can have different streams.

## What Is A Stream?

A stream is the selected version line of a module.

Example:

```text
nodejs:16
nodejs:18
nodejs:20
```

Meaning:

```text
nodejs:16  use the NodeJS 16 stream
nodejs:18  use the NodeJS 18 stream
nodejs:20  use the NodeJS 20 stream
```

The stream is not always available just because the upstream project has that version.

It must exist in your enabled repositories.

## List Available Modules

List all modules:

```bash
sudo dnf module list
```

This can produce long output.

To search for NodeJS:

```bash
sudo dnf module list nodejs
```

Example output may show:

```text
Name    Stream    Profiles
nodejs  18        common, development, minimal
```

Meaning:

```text
The nodejs module is available.
Stream 18 is available.
```

## Check Current Node Version

Before changing the module:

```bash
node --version
```

Example:

```text
v16.19.0
```

This means the current installed NodeJS binary is version 16.

## Enable A Module Stream

To enable the NodeJS 18 stream:

```bash
sudo dnf module enable nodejs:18
```

DNF will ask for confirmation.

Confirm with:

```text
y
```

Important:

```text
Enabling a module stream does not necessarily upgrade the installed package immediately.
```

It tells DNF which stream should be used.

## Upgrade After Enabling A Stream

After enabling the stream, run:

```bash
sudo dnf upgrade
```

This upgrades installed packages to versions from the enabled stream where possible.

Then check:

```bash
node --version
```

Example:

```text
v18.x.x
```

Meaning:

```text
NodeJS is now running from the NodeJS 18 stream.
```

## Why Enabling A Module Is Controlled

The default repository version stays stable.

Newer streams are available only when you choose them.

This gives administrators control.

Example:

```text
Developers test the application with NodeJS 18.
Administrator enables nodejs:18.
DNF upgrades NodeJS on purpose.
```

This is better than surprise upgrades.

## Modules Over Time

During one OS release, more streams may become available.

Example:

```text
At first, only nodejs:16 is available.
Later, nodejs:18 is added.
Later, nodejs:20 may be added.
```

The default version can stay stable, while newer streams are available for systems that need them.

## Module Profiles

Modules can have profiles.

A profile is a predefined set of packages inside a module stream.

Example:

```text
module: nodejs
stream: 18
profiles: common, development, minimal
```

The stream chooses the version line.

The profile chooses which package set from that stream should be installed.

Example:

```text
nodejs:18/common       normal NodeJS tools
nodejs:18/development  NodeJS plus development-related tools
```

This means:

```text
stream = which version line
profile = which preset package group
```

## List Module Profiles

To see available streams and profiles:

```bash
sudo dnf module list nodejs
```

Example output may show:

```text
Name    Stream    Profiles
nodejs  18        common, development, minimal
```

Meaning:

```text
NodeJS stream 18 is available.
It has multiple profiles.
```

## Install A Module Directly

You can install a module directly:

```bash
sudo dnf module install nodejs
```

You can also specify the stream:

```bash
sudo dnf module install nodejs:18
```

And you can specify the profile:

```bash
sudo dnf module install nodejs:18/development
```

Meaning:

```text
Install the NodeJS module.
Use the NodeJS 18 stream.
Install the development profile package set.
```

The most specific form is:

```bash
sudo dnf module install MODULE:STREAM/PROFILE
```

Example:

```bash
sudo dnf module install nodejs:18/development
```

If you leave out the profile, DNF uses the default profile.

Example:

```bash
sudo dnf module install nodejs:18
```

This usually installs the default profile, such as `common`.

## Install A Module With Normal DNF Install

There is also another syntax:

```bash
sudo dnf install @nodejs:18
```

The `@` tells DNF that you are referring to a module/group-like install target, not just a normal package name.

Depending on the system and DNF version, you may also see module/profile syntax used with `@`.

The clearer command for learning is:

```bash
sudo dnf module install nodejs:18/development
```

## Remove A Module Profile

To remove a module profile:

```bash
sudo dnf module remove nodejs:18/development
```

This removes the packages installed by that profile.

Important:

```text
dnf module remove does not necessarily disable or reset the module stream.
It removes the installed profile package set.
```

Example:

```bash
sudo dnf module remove nodejs:18/development
```

Meaning:

```text
Remove the development profile packages from the NodeJS 18 module.
```

After this, the stream may still be enabled:

```bash
sudo dnf module list nodejs
```

You may still see:

```text
nodejs  18  [e]
```

Meaning:

```text
The NodeJS 18 stream is still enabled.
Only the development profile packages were removed.
```

## Remove All Software From A Module

To remove all software provided by a module stream:

```bash
sudo dnf module remove --all nodejs
```

Meaning:

```text
Try to remove all installed packages that came from the nodejs module.
```

This is stronger than removing one profile.

Before confirming, read the transaction carefully.

Example:

```text
Removing:
  nodejs
  nodejs-docs
  npm
```

Only confirm if that is what you want.

## Disable A Module

To disable a module:

```bash
sudo dnf module disable nodejs
```

Meaning:

```text
Stop using this module stream for future package choices and updates.
```

Important:

```text
Disabling a module does not uninstall the software.
```

Example:

```bash
sudo dnf module disable nodejs
```

Then:

```bash
node --version
```

NodeJS may still be installed.

The difference is:

```text
NodeJS binary remains on the system.
DNF no longer treats the module stream as enabled.
```

## Reset A Module

To reset a module:

```bash
sudo dnf module reset nodejs
```

Meaning:

```text
Remove the module configuration choice.
Return the module to neutral/default state.
```

Important:

```text
Resetting a module does not uninstall the software.
```

After reset, the module is neither enabled nor disabled.

Check:

```bash
sudo dnf module list nodejs
```

The module should no longer show as enabled or disabled.

But the package may still exist:

```bash
node --version
```

This can still show NodeJS installed.

## Disable vs Reset vs Remove

These commands sound similar, but they do different things.

```text
dnf module remove PROFILE
removes packages installed by a module profile
```

```text
dnf module remove --all MODULE
tries to remove all installed packages from that module
```

```text
dnf module disable MODULE
keeps installed software, but disables the module stream for future use
```

```text
dnf module reset MODULE
keeps installed software, but removes the module enabled/disabled choice
```

Short version:

```text
remove = remove packages
disable = stop using module stream
reset = forget module configuration
```

## Tricky Case: Package Was Installed Before Module

Sometimes NodeJS was installed before you enabled the module.

Example:

```bash
sudo dnf install nodejs
sudo dnf module enable nodejs:18
sudo dnf upgrade
```

Now NodeJS may be version 18.

But DNF may still remember that `nodejs` was originally installed as a normal user-installed package, not only as a dependency of the module profile.

In that case:

```bash
sudo dnf module remove nodejs:18/common
```

may not remove NodeJS itself.

Why:

```text
DNF does not want to uninstall a package that was installed directly by the user before the module profile.
```

So after removing/resetting the module, this may still work:

```bash
node --version
```

## Returning From NodeJS 18 Back To Default Repo Version

If NodeJS 18 came from a module and you want to return to the default repository version, the safe workflow is:

1. Make sure the module stream is available/enabled again.

```bash
sudo dnf module install nodejs:18
```

2. Remove all software from that module.

```bash
sudo dnf module remove --all nodejs
```

3. Reset the module configuration.

```bash
sudo dnf module reset nodejs
```

4. Install NodeJS normally from the default repositories.

```bash
sudo dnf install nodejs
```

5. Check the version.

```bash
node --version
```

Expected:

```text
NodeJS is installed again from the normal repository/default version.
```

This can look more complicated than expected because modules affect package selection, but they do not always automatically remove packages that were installed before the module was enabled.

## Important Warning

Always read the DNF transaction before confirming.

Commands like this can remove many packages:

```bash
sudo dnf module remove --all nodejs
```

DNF will show what it plans to remove.

Only type `y` if the package list makes sense.

## Summary

DNF modules are package groups with selectable version streams.

They are useful for software where version choice matters.

Examples:

```text
NodeJS
PHP
PostgreSQL
Redis
MariaDB
```

Important terms:

```text
module  package group, often an application or runtime
stream  version line of that module
profile predefined package set inside a module stream
```

Typical workflow:

```bash
sudo dnf module list nodejs
sudo dnf module enable nodejs:18
sudo dnf upgrade
node --version
```

Install a specific profile:

```bash
sudo dnf module install nodejs:18/development
```

Remove a profile:

```bash
sudo dnf module remove nodejs:18/development
```

Disable a module without uninstalling software:

```bash
sudo dnf module disable nodejs
```

Reset module configuration without uninstalling software:

```bash
sudo dnf module reset nodejs
```

This lets you opt in to a newer supported version while keeping the rest of the enterprise Linux system stable.
