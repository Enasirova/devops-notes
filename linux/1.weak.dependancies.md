 depancies:
* required depenacies = essential for OS. without them we cannot execute the program
* weak dependances = optional. they enhance the functionality
    * recomends = package recommends another package. most users want to install this other package
    * suggests = this package can use another pacakte but usually we wouldnt need this other package.

by deafult dnf will install recommended weak dependancies as well (if it doesnt trigger a conflict)

how we can list the weak dependacies:
 `dnf repoquery --recommends [package_name]`

 `dnf repoquery --suggests [package_name]` (mostly for informational purposes)

# sudo dnf repoquery

sudo dnf repoquery runs DNF's package query subcommand with root privileges.

In practice:

sudo runs it as administrator.
dnf is the package manager on Fedora/RHEL-like systems.
repoquery queries package metadata from enabled repositories.
It does not install anything by itself. It is mainly used to inspect packages, for example:

sudo dnf repoquery vim shows matching package info.
dnf repoquery --requires nginx lists dependencies.
dnf repoquery --whatprovides /usr/bin/python3 finds which package provides a file.


#
In CentOS, you are querying the RPM/DNF package database and enabled repos for package relationships.

`sudo dnf repoquery --recommends python3`
means:

find the package named python3
show its Recommends entries, which are weak dependencies
That output:

`/usr/bin/python`
means the python3 package recommends that something provide the file /usr/bin/python. It is not showing a package name there because RPM metadata can express dependencies as file paths, not just package names.

`sudo dnf repoquery --whatprovides /usr/bin/python` -> That should show which package provides that path on your configured repos.

# RPM

Red Hat Package Manager


It usually refers to two related things:

* .rpm files, which are software packages
* the rpm tool, which installs, queries, verifies, and removes those packages at a low level

What RPM does:

* stores files for a program
* includes metadata like name, version, dependencies, scripts
* tracks installed packages in the RPM database

```bash
~$ rpm -q bash
bash-5.2.26-6.el10.aarch64
~$ rpm -q python
package python is not installed
~$ rpm -q python3
python3-3.12.12-3.el10.aarch64
~$ 
```

## rpm:

* low-level package tool
* works directly with .rpm packages and the local RPM database
* does not reliably resolve dependencies for you like dnf does

## dnf:

* higher-level package manager
* uses RPM underneath
* resolves dependencies automatically
* downloads packages from repositories
* is the normal tool for installing software

Example:

`sudo rpm -ivh package.rpm`
installs a local RPM file directly.

`sudo dnf install package-name`
installs a package and pulls required dependencies from repos.
