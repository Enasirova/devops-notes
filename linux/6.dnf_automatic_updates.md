# DNF Automatic Updates

## What This Is About

This note explains how to configure automatic updates with DNF.

Main idea:

```text
Automatic updates can keep a non-critical system up to date.
Critical servers should usually be updated manually during planned maintenance windows.
```

## Important Warning

Do **not** blindly enable automatic updates on critical servers.

A critical server means:

```text
A server where unexpected downtime would cause business impact.
```

Examples:

- production application server
- database server
- payment system
- customer-facing service
- important Jenkins controller or build infrastructure

For critical servers, updates should usually be planned and performed manually.

Why:

```text
You can choose a low-traffic time.
You can be available if something breaks.
You can test or snapshot first.
You can coordinate with users or teams.
```

## When Automatic Updates Can Make Sense

Automatic updates may be reasonable when:

```text
The machine is not critical.
Unexpected downtime is acceptable.
The system can be rebuilt easily.
The risk of missing updates is worse than the risk of an update problem.
```

Examples:

- personal virtual machine
- test server
- lab machine
- disposable development machine
- non-critical internal tool

This is a judgment call.

Automatic updates are not always wrong, but they should be enabled intentionally.

## Install DNF Automatic

The tool used for automatic DNF updates is:

```text
dnf-automatic
```

Install it:

```bash
sudo dnf install dnf-automatic
```

DNF may show the package transaction and ask for confirmation.

Confirm with:

```text
y
```

## Configuration File

The main configuration file is:

```text
/etc/dnf/automatic.conf
```

Open it with a text editor.

Example:

```bash
sudo vi /etc/dnf/automatic.conf
```

or:

```bash
sudo nano /etc/dnf/automatic.conf
```

## Upgrade Type

In `/etc/dnf/automatic.conf`, look for:

```ini
upgrade_type = default
```

This controls what kind of upgrades are allowed.

Common values:

```text
default
security
```

Meaning:

```text
default   install all available upgrades
security  install only security updates
```

For example, to install only security updates:

```ini
upgrade_type = security
```

This can be a more conservative choice than installing every available update automatically.

## Download Updates Automatically

Look for:

```ini
download_updates = yes
```

Meaning:

```text
DNF automatic may download updates automatically.
```

If set to:

```ini
download_updates = no
```

then updates are not downloaded automatically.

## Install Updates Automatically

Look for:

```ini
apply_updates = no
```

Meaning:

```text
Updates may be downloaded, but they are not installed automatically.
```

To actually install updates automatically, set:

```ini
apply_updates = yes
```

For a non-critical virtual machine, this may be acceptable.

For a critical server, be careful.

## Example Configuration

Example for automatic security updates only:

```ini
[commands]
upgrade_type = security
download_updates = yes
apply_updates = yes
```

Meaning:

```text
Download and install security updates automatically.
Do not automatically install every normal bug fix or feature update.
```

Example for downloading only:

```ini
[commands]
upgrade_type = default
download_updates = yes
apply_updates = no
```

Meaning:

```text
Download available updates.
Do not install them automatically.
```

## Enable The Systemd Timer

`dnf-automatic` is usually run by a systemd timer.

Enable it:

```bash
sudo systemctl enable dnf-automatic.timer
```

Start it now:

```bash
sudo systemctl start dnf-automatic.timer
```

You can do both with:

```bash
sudo systemctl enable --now dnf-automatic.timer
```

Meaning:

```text
Enable it at boot.
Start it immediately.
```

## Check Timer Status

Check whether the timer is active:

```bash
systemctl status dnf-automatic.timer
```

List timers:

```bash
systemctl list-timers
```

Or filter for DNF:

```bash
systemctl list-timers | grep dnf
```

Expected:

```text
dnf-automatic.timer should be listed and active.
```

## Run DNF Automatic Manually

To test it manually:

```bash
sudo systemctl start dnf-automatic.service
```

Then check status:

```bash
systemctl status dnf-automatic.service
```

You can also check logs:

```bash
journalctl -u dnf-automatic.service
```

## What Happens After Enabling It

After enabling the timer:

```text
The system periodically runs dnf-automatic.
Depending on configuration, it may download updates.
Depending on configuration, it may also install updates.
```

If `apply_updates = yes`, the machine can change package versions without you manually running:

```bash
sudo dnf upgrade
```

This is useful on non-critical systems.

It can be dangerous on critical systems.

## Possible Problems

Automatic updates can cause issues at unexpected times.

Examples:

```text
A service restarts during working hours.
A package update changes behavior.
A kernel update requires a reboot.
An application is not compatible with the updated package.
A dependency problem blocks the automatic update.
```

This is why automatic updates should be considered carefully.
